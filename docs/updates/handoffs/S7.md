## Doc changes
- `docs/API.md`: new section "Feedback" with
  - `POST /api/feedback/:reportId`: auth; citizen who owns the report; report `resolved`. Body `{ rating: 1–5 integer, comment?: string ≤ 500 }`. 201 `{ feedback }`. 400 invalid body or report not resolved, 403 not the owner, 404 no such report, 409 "You have already rated this report." Notifies the assigned staff member; logs `feedback.created`.
  - `GET /api/feedback/:reportId`: auth; same visibility as the report (owner, assigned staff, admin). 200 `{ feedback: { id, report_id, rating, comment, created_at } | null }`.
  - `GET /api/feedback/summary/staff`: staff or admin. Staff get their own; an admin may pass `?staff_id=<uuid>` or omit it for all ratings. 200 `{ summary: { staff_id, average, count } }` (`average` null when `count` is 0). Staff passing another `staff_id` get 403.

## Migration notes
- File: `supabase/migrations/20261003000500_feedback.sql`. Depends only on the six existing migrations (`reports`, `profiles`, `gen_random_uuid()`). It does not touch any other stream's tables, the `update_type` enum, or `public_reports`.
- Creates table `public.report_feedback`: `id uuid pk`, `report_id uuid unique not null → reports ON DELETE RESTRICT`, `citizen_id uuid not null → profiles RESTRICT`, `staff_id uuid null → profiles RESTRICT`, `rating smallint check 1–5`, `comment text null check (≤ 500 chars and not blank)`, `created_at timestamptz default now()`.
- Index `report_feedback_staff_idx (staff_id, created_at desc) where staff_id is not null`.
- RLS enabled, no policies. `revoke all` from public/anon/authenticated. `service_role`: `select, insert` only (no update/delete → immutable).
- Function `public.feedback_summary(p_staff_id uuid default null) returns table(average numeric, total bigint)`, `stable`, `search_path = ''`. Execute revoked from public/anon/authenticated, granted to service_role.
- No backfill. To check after applying (on a local/disposable project): `\d public.report_feedback`; `select * from public.feedback_summary();` returns one row `(null, 0)`; as `authenticated`, `select` on `report_feedback` is denied.
- S5's `profiles → auth.users` restrict change does not conflict: this table only references `profiles`.

## Judgment calls and limitations
- **`staff_id` column added** (not in the brief's column list). It records the assignee when the rating is given, so a report reassigned after resolution does not move the rating to someone who did not do the work, and the staff average is a plain indexed filter. The notification goes to the same person.
- **Average computed in SQL** (`feedback_summary()` via `db.rpc`) instead of loading every rating into Express, because supabase-js caps rows at the API's max-rows setting and would silently undercount.
- **Admin summary without `staff_id`** returns the average across all ratings (useful for the dashboard). Staff always get their own; a staff caller passing a different `staff_id` gets 403 rather than having it silently ignored.
- **Duplicate → 409** "You have already rated this report." (checked first, and the unique index's `23505` maps to the same 409 for a race).
- **Notification failure after the rating is saved** is logged and swallowed (same pattern as `notifyNewReport`), changed in orchestrator review: a 500 after a saved rating made the citizen retry into "already rated". The rating stays and the staff page still shows it.
- **No history row** (see breadcrumb): the `update_type` enum belongs to S4.
- **Who is notified**: only the assigned staff member, not admins (FB-1 says "route that feedback to the assigned staff member"). Unassigned report → no notification, rating still saved with `staff_id` null.
- **Admins and staff cannot rate**, even though admins can view every report.
- **Form rules**: the submit button stays disabled until a rating is chosen (the project's KR-07 rule), and the rating error appears once focus leaves the group without a choice. No `beforeunload` warning: a rating plus at most 500 characters did not seem to justify one.
- **Rating scale words**: 1 Poor, 2 Fair, 3 Good, 4 Very good, 5 Excellent. Visible under each number; the five-square meter in the read-only view is `aria-hidden` and neutral-coloured (no red, which the design system reserves for the accent and errors).
- **Route reuse**: the form keys its local state to the report id, because React Router keeps `ReportDetailPage` mounted when only `:id` changes.
- **Tests** swap `db.from`/`db.rpc` on the shared client for a small fake and restore them after each test; no network or database is used.
