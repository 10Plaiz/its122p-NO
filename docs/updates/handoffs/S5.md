## Migration notes
- `20261003000100_no_delete.sql`: drops and re-adds 8 foreign keys as `ON DELETE RESTRICT` (report_photos, report_updates, report_inspections, notifications x2, profiles→auth.users, reports.assigned_staff_id, activity_logs.actor_id); adds `report_photos.purged_at` and a partial index.
- Constraint names are Postgres defaults. The final `do` block raises if any cascade/set-null/set-default key remains on those tables, so a renamed constraint on the live DB fails loudly instead of being skipped.
- Re-adding a key validates existing rows; orphans would fail the migration. Run `db push --dry-run` first.

## Judgment calls and limitations
- The two `set null` keys became `restrict` too: with profiles never deleted they never fire, and if they did they would blank the audit trail.
- Purge removes files first, then stamps rows; a failed stamp is fixed by the next run because removing a missing file is a no-op.
- A failed batch returns 500 with the counts so far and is still logged.
- `tests/browser/cleanup.ts` is the documented exception to DM-1 (disposable fixture project only).
